# Adobe Firefly 接入

Adobe HME、重新登录与生成会话修复已与账号默认出口整合，`main` 的 `76e3f00` 于
2026-11-11 上线。本轮补齐 Adobe 浏览器对带认证 SOCKS5 默认出口的兼容。
验证日期：2026-11-11（Asia/Shanghai）。免费模型权益、余额与上游协议可能变化。

## 模型与统一接口

调用方只指定逻辑模型和参数；无需也不能通过 provider/channel 指定渠道。现有 ChatGPT 和
Grok 模型 ID 保留。Adobe 模型沿用 CFM 的 `/v1/images/generations`、`/api/image-tasks/generations`
以及 `/v1/videos` 接口。`/v1/models` 和管理目录返回能力组合，Studio 仅展示模型和对应参数。

当前目录包含新免费账号在官方 `generation-preflight` 中确认授权的 8 个图片模型、6 个视频模型。
权限检查通过与生成完成分别记录；11月12日本地Nano Banana 2.1生图和Omni Flash 1.2
720p/5秒/音频已通过统一接口实测，
其他组合仍以各次记录为准，不能宣称全部模型已实测生成成功。

同步生图示例：

```json
{"model":"gemini-3.1-flash-image","prompt":"A blue ceramic vase on a white table","n":1,"size":"1024x1024","response_format":"url"}
```

视频为 multipart：model=veo-3.1-lite、prompt、seconds=8、size=1920x1080、
resolution_name=1080p、generate_audio=true/false；参考图复用现有 multipart 图片字段。`Idempotency-Key` 或 `client_task_id` 提供幂等，
重复调用返回原任务，不重新生成；不同输入使用同键返回 409。

## CFM 内部路由

系统设置中的渠道优先级仅在一个逻辑模型有多个合格渠道时显示。管理接口：
`GET /api/model-routing` 返回 models（model/name/channels/priority）；
`PUT /api/model-routing` 接受 `{"priorities":{"逻辑模型":["chatgpt","adobe"]}}`。
单渠道模型无需配置；新合格渠道追加到既有顺序之后。配置只影响以后首次选择的任务。

选择前检查完整参数组合、有效凭据、已确认额度与账号占用；无合格账号可检查下个候选渠道。
一旦选定渠道和账号，立即持久化绑定，后续失败不跨渠道、不换账号、不重发生成 POST。
这也适用于现有 GPT/Grok 媒体生成和内容核对；文本请求和注册恢复的独立策略不受影响。
GPT 多图批次固定同一账号，按顺序生成，预留整批额度；任何失败立即终止剩余输出。

Adobe 将额度调度与媒体会话准备分开：先按模型权益、额度、启用状态、占用和冷却筛选，
优先选择当前出口下媒体会话已就绪的账号，同级按最久未使用选择。仅正常浏览器采集并成功
保存的会话可以进入进程内缓存；导入字段、登录Token有效或余额可查均不能证明会话就绪。
模型权益在绑定前区分“新鲜可用、新鲜不可用、需要查询”，过期或缺失不直接参与选号。
前台按本次模型只读刷新，最多观察4个候选，与后台自动维护开关独立；计数型免费资源
要求新鲜授权、匹配资源池、有效余额和成本，明确授权的fair_use允许无计数但不显示无限。
查询失败使用与账号身份、凭据和实际出口绑定的30秒本地退避，并发请求共享结果；
退避账号不占实际查询预算。新鲜但仍在媒体冷却或出口不可用的账号也不能阻止检查其他候选。
最终加锁绑定再次核对权益新鲜度、额度版本及可用性；完整参数的上游preflight继续保留。
缓存采用5分钟本地复用窗口，登录Token至少需余1分钟；成功调用不延长窗口。凭据、身份、
profile、媒体内容或实际解析后的出口变化，以及服务重启，均不能复用旧记录。该窗口是
CFM的保守调度策略，不是已确认的Adobe媒体令牌有效期，也不保证动态代理背后的公网IP不变。
后台重新登录先固定账号实际出口，再将同一上下文传入存储和浏览器；成功采集后可直接
建立可信缓存。2026-11-12第二测试账号连续两张Nano Banana 2.1实际生成均命中缓存，
准备耗时5ms/4ms、全程22.462s/20.553s，凭据版本与采集时间未变化；详见协议验证记录。

沿用30秒后台巡检及Adobe自动维护开关，仅对最近10分钟使用且有明确可用免费模型权益的
空闲账号预热，剩余窗口不足1分钟时更新；每轮最多采集1个，已有2个就绪账号则跳过。
未使用的账号不持续启动浏览器。前台请求与后台预热共用账号维护保护，已有预热时等待
同一次结果；未就绪时选定账号后只采集一次。准备失败独立退避，避免连续请求反复占用
Grok共用的浏览器队列。关闭自动维护后，前台必要的会话准备仍保留。
额度及模型权益查询在同一维护保护范围内完成，只读额度更新不刷新媒体缓存期限。
后台按最早到期排序，每轮最多4个实际额度查询；忙碌账号不占查询名额，进入维护保护后
再次判断是否到期。请求在绑定前可有界等待同账号正在进行的维护，避免唯一账号正在查询
时误报无可用账号。浏览器采集失败通常退避5分钟，要求登录或验证时退避15分钟，重启保留。
最终身份与媒体会话校验允许官方observable异步送达首值，默认最多等待1.5秒；已确认的
身份、令牌、认证实例或SDK生命周期证据变化仍立即拒绝。失败任务可显示
`[vendors_pending]`、`[identity_pending]`、`[runtime_changed]`等固定原因；诊断只保留
白名单类别和有界计数，不包含令牌、Cookie、原始SDK实例或网络载荷。
初始`unavailable`已拆分为`authentication_missing`、`arp_observer_missing`、
`editor_route_changed`、`page_hidden`、`observation_cancelled`、`evaluation_failed`和
`navigation_budget_exhausted`。Worker仅在失败时附加固定页面类别、有界候选计数及初始化
时间/变化次数；这些辅助观察不替代身份或媒体就绪校验，默认30秒预算保持。

命中就绪会话时只记录本任务准备标记，随后以HTTP完成免费权益预检、参考图上传和生成；
未命中才由共享browser-worker正常采集，再以新凭据继续。提交错误使对应版本的媒体缓存
失效；原任务仍按原渠道和账号处理，不自动重新生成。
缺少已保存的浏览器profile、会话采集失败或账号并发变化时，结束这次未提交任务并保留原因，
不静默使用旧会话、不换账号。重复幂等请求及已受理任务的轮询/下载不重新执行生成前准备。
服务中断后，后台只在磁盘中的唯一任务仍明确停在提交前、任务已终止且无上游句柄时，
记录 `not_submitted` 并结束本地预留；记录损坏、任务执行中或已进入提交阶段时不采用此路径。

Adobe 在收到上游任务句柄后加密保存，只在明确 COMPLETED 后交付资源，不能用 progress=100
或提前出现的下载地址判定完成。重启及后台处理恢复已有句柄的轮询与下载；没有句柄的未知提交
按下述自动处理规则结束本地占用，原结果仍未知，不重新提交。轮询/下载中断也可通过图片或视频任务 `/resume-poll` 恢复。
恢复使用原账号和原代理绑定，管理员更改模型优先级不能改变已有任务。

## 账号、额度与注册

注册和账号管理各有独立 Adobe 标签，邮箱平台占用/禁用/已使用状态独立；删除其他平台账号
不能误释放 Adobe 占用。Adobe 注册地区固定为美国，每个新任务自动生成实际年龄 25–50 岁的
合法出生日期，保存在加密任务记录中；同一任务恢复沿用原日期。页面不再提供地区、生日
或验证码等待/轮询配置，旧地区/生日配置在读取和保存时清理。

验证码复用 GPT/Grok 的共享 HME 邮箱资源管理器，使用所选邮箱来源自动领取、收码和
记录归属。Adobe 使用统一的内置收码等待/轮询策略，不读取其他渠道遗留的时间设置；
邮件同时检查 Adobe 发件人、目标邮箱和时间窗口，并识别 HME 的 iCloud 转发地址。
注册设置、调度、结果恢复记录分别保存。可恢复的临时失败按 5 分钟、30 分钟、2 小时退避，
同邮箱跨任务链最多自动补偿 3 次，重启不重置次数和冷却。页面显示等待、
执行中、已尝试次数、下次执行时间及次数耗尽，并保留首次任务、来源任务和后续尝试链。
任务返回 `can_retry_registration` 时可“补偿注册”，返回 `can_resume_registration` 时可
“恢复注册”；两者都调用 `POST /api/register/adobe/retry-registration`，只提交 `{ "id": "任务 ID" }`，
由服务器核定恢复方式。已提交注册结果未知时只恢复原会话和检查结果，不再次点击创建账户。
Go 对曾启动浏览器流程的任务保守选择恢复；Worker 读取并锁定原 profile 的持久记录，
仅在明确尚未提交创建时继续原注册步骤，保留已提交的邮箱/密码阶段标记。创建标记一旦写入，
后续只恢复会话、正常登录和 HME 邮件验证。缺失或不安全的原记录不得新建 profile 代替。
取得账号但导入或校验失败时，`can_retry` 仍只开放“重试入库 / 校验”，该路径不依赖当前
HME 来源配置，也不重新打开浏览器。所有尝试沿用原邮箱占用归属，保留历史父子任务。
补偿独立于批次定时开关和当前页面标签；维护/部署暂停期间不执行。主动停止取消待执行补偿；
服务正常退出保留延期恢复计划。旧失败记录在后台调度时纳入补偿，不在冻结候选实例构造时迁移。
邮件验证码复用邮箱管理器；持续的人机验证会结束当前尝试，后续恢复受退避及次数上限约束，仍须通过 Adobe 校验，
不绕过验证。浏览器参与注册、登录态维护及新生成前的会话准备，图片与视频生成
请求、轮询及下载仍由 Go HTTP 完成。

Worker 对验证框、可见验证提示或暂态验证响应最多只读观察 15 秒，允许 Adobe 自行完成校验
后继续 HME 收码及登录。持续验证或明确网络故障仍会结束当前尝试，保留原提交；
不重新点击创建账户。同一恢复任务不反复追加观察窗口，新的补偿任务可独立观察一次。
记录固定检测来源、最近至多 8 条脱敏资源事件的开始/观察时间和浏览器关闭时间，
不记录原始 URL、响应、挑战内容或凭据。观察时间与请求被取消的精确发生时间分别理解。
旧版未保存检测依据的失败无法事后判定为真正挑战或瞬态误判。本机工具曾保留浏览器供继续
观察，而 Worker 在流程返回后释放浏览器；本机成功不能作为相同邮箱在线上重注册的依据。

注册和重新登录均通过共享 `cfm-browser-worker` 排队执行。Adobe 的 CloakBrowser 驱动支持
HTTP、HTTPS、SOCKS5（含用户名/密码）代理；`socks5h` 按 Chromium 的远端域名解析行为
规范化为 `socks5`。重新登录遵循账号日常出口配置，不因代理失败自动改为直连。
普通 Playwright 后端仅支持无认证 SOCKS5，认证配置会在启动前明确拒绝。

`/api/adobe/accounts` 及其 import/refresh/relogin/disabled/link-mailboxes 子接口只允许管理员。列表采用安全字段白名单，
不返回 Cookie、令牌、密码、Sherlock、代理凭据或浏览器资料。凭据按账号身份和版本校验后更新；
刷新返回其他身份时拒绝覆盖。IMS 刷新失败可使用原 browser profile，仍须核对相同身份。
后台维护与生成占用互斥，不能在提交失败后刷新并重发生成。

令牌刷新与媒体会话更新分别显示。ARP 会话按官方客户端的不透明值原样转发，不要求或拼装
`sid/ark/bfp/ftr` 等内部字段；新账号合法导出可能只有 sid/ftr。仅取得新 Token/IMS Cookie 而
没有新媒体会话时保留已有值，不能把令牌刷新成功解释为媒体会话已续期。
2026-11-11 继续核对官网宿主初始化与 SPL/UGS 源码：ARP 初始值为 null，身份已登录或
编辑器组件已出现不代表媒体初始化完成。11 月 12 日被动观察还发现首次非空值之后仍在更新。
新采集在原 30 秒截止内等待当前页面单一 SDK 实例的已知异步回调证据，再要求官方值与
性能记录连续 250ms 不变；这个短窗口只检查收尾一致性，不代表上游认证或生成成功。
多实例、缺少回调证据或超时均保留原凭据，不按令牌长度/内部字段判断或拼装。
最终身份复核后，再核对同一 SPL 实例的账号、Access Token、登录状态、媒体令牌和性能记录。
性能明细只在内存检查，不落入账号存储。初始化空值不再导出为 omitted。
CFM 继续兼容已有 `media_session_arp_mode`（`present` / `omitted`）和
`media_session_arp_source=spl_runtime` 记录；两字段缺失的旧记录仍必须提供有效 Sherlock。
半缺或未知标记拒绝。`present` 要求有效媒体 Token；`omitted` 不得携带旧 Sherlock，提交时完全
不设置该请求头，不能发送空值；该兼容不证明旧会话仍可生成。正常浏览器维护必须采集非空官方值后替换媒体 Cookie；IMS Token
刷新只保留原策略，不能自行建立省略状态。管理员可以显式导入完整已知组合，导入状态仍为
“已导入”，不宣称刚完成浏览器认证。参考图上传前、账号选择和最终提交使用相同校验。


账号页分别显示 `quota.generation.pools` 中的共享免费额度，不按模型复制或合并为一个总次数。
本次新账号返回：图片池 3 次/日、视频池 1 次/日、GPT Image 2 独立 3 次体验池；实际数值及
刷新周期以各账号接口为准。`quota.available` 的 10/0/10 是通用积分，不能代替这些生成额度。
未知、查询失败、过期与明确零值分开。已成功查询的额度快照超过 5 分钟后保留上次数值和
查询时间，页面明确标为“待刷新”，不将历史数值当作当前可用额度；已检查通过的账号不会仅因
快照过期变为“待检查”。未曾查询或查询失败仍单独提示，凭据异常、过期和禁用状态保持。
闲置账号后台每小时检查，近期使用账号每 5 分钟检查；展示旧快照不会放宽实际生成的权限校验。
选择账号前按目标模型过滤新鲜、明确不可用的额度；未知额度由精确 preflight 判定。
已绑定后失败不换账号或渠道，408 按提交结果未知保留，不重发。
生成仍独占账号，结束后等待结算并重新查询，既不假定每次固定扣 1，也不据积分不变推断无限。

账号页与 GPT/Grok 共用“全选当前结果、账号总数、已选数量、列表/卡片视图”控件，Adobe 视图偏好独立保存。
Grok 和 Adobe 工具栏均提供“批量操作”入口，无选择时禁用；勾选后同时显示浮动批量操作栏。
Adobe 每行及卡片提供“刷新额度”和“更多”菜单，可单独刷新登录态、关联邮箱资产、启用/禁用或删除。
单行操作仅作用于当前账号，删除确认固定目标账号，取消不会执行删除。

列表和卡片另有“重新登录”，批量菜单支持逐账号串行重新登录。管理员接口为
`POST /api/adobe/accounts/relogin`，请求
`{"request_id":"本次操作唯一 UUID","ids":["adobe:账号标识"]}`，每批 1–100 个账号。
接口快速返回 HTTP 202 和任务列表；浏览器排队、登录由后台串行执行。页面使用
`GET /api/adobe/accounts/relogin` 轮询，也可按 `?request_id=...` 核对受理结果；刷新页面后继续查询。
POST 丢失响应时只查询进度，不自动再次提交，也不逐账号继续发送新请求。相同 request_id
幂等返回原任务；同账号已有进行中的登录任务时复用该任务。
它直接进入共享浏览器队列，使用账号原有 profile 和出口执行官网登录及媒体会话初始化，
与优先调用 IMS 的“刷新登录态”分开。成功要求官网运行时媒体会话就绪、有效 Token、账号身份一致，
且 Cookie 与本次 ARP 策略一致；仅取得新 Token 或保留旧 Cookie 不视为重新登录成功。
官网可能复用同一个媒体 Token，因此不以 Cookie 字符串是否变化判断成功。
专用 Worker 重新登录不传 `--restore-last-session`，保留原 profile、Cookie 和浏览器 seed；
Playwright 会等待恢复页初始化后才返回 context，因此仅在启动后关页无法避免启动阶段的争用。
启动后仍检查并关闭专用 context 中的多余页面，确认只保留一页再导航；关闭失败或新页竞争时停止。
独立工具默认保留恢复标签行为，不影响用户日常浏览器。启动失败在 Worker 队列中增加固定
`diagnostic_code`，区分超时、代理、profile、进程退出和许可错误，不透传原始错误或启动参数。
媒体观察超时区分已观察到空值的 pending、缺少来源的 unavailable 与页面未返回的
observation_timeout；这些状态均不表示生成权限已通过。

真正生成中、结算等待或维护中的账号拒绝并发重新登录。提交结果未知的账号显示“系统处理中”，
可以重新登录恢复认证，但原任务占用、账号绑定、错误记录和历史结果全部保留，不重发任务、
不换账号；占用由独立后台任务按下述规则处理，重新登录本身不解除占用。重新登录失败保留原凭据；邮件验证、额外身份验证、登录未完成
及媒体会话未就绪分别提示。成功提交凭据使用版本校验，避免覆盖并发更新，手动禁用状态保持。
任务元数据保存在 `data/adobe_relogin_tasks.json.enc`，包含在核心备份范围内，不包含登录凭据。
正在执行的批次计入发布排空；维护模式拒绝新受理，进度查询仍可用。持有独占数据租约的实例
启动时将旧的未完成记录标为“结果待核对”，不自动重跑；候选实例和 GET 查询不改写日志。
排队后的账号凭据版本发生变化时，后台任务停止，避免覆盖新的会话。

### 登录状态、额度查询与任务自动处理

账号页将登录状态和生成任务占用分开展示。重新登录成功可以显示登录态有效，同时仍显示
“系统处理中”；这表示旧生成结果尚未确认，并不代表重新登录失败。历史生成错误码不再显示
在邮箱下方，原任务及其错误记录继续保留。

管理员的“刷新额度”（`POST /api/adobe/accounts/refresh`，`credentials:false`）只使用现有
凭据查询积分和免费生成权限。即使有未知任务占用也可查询，不打开浏览器、不刷新登录态、
不清除占用、不发送生成请求；凭据失效时应先重新登录。查询期间若凭据、任务或结算状态变化，
旧查询结果不会覆盖新状态。系统后台的凭据维护仍按原有互斥规则执行。

后台每30秒检查一次，每批最多处理4个账号，启动后首次检查约1分钟。该任务处理独立于
`adobe_maintenance.enabled` 的登录态维护开关，但遵守部署暂停、维护标记和单写实例限制。

- 已有可信任务地址：仅恢复原任务的查询和下载；不换号、不换渠道、不提交新生成。
  本地执行中或正在恢复的任务不会被并发处理；失败检查按持久化时间退避。
- 没有任务地址：从原任务占用时间起保留30分钟，自动尝试查询额度。期限届满后，在本地
  任务已停止且账号版本、任务绑定未变时，原子保存系统审计并解除本地占用。
  旧记录的占用时间缺失或在未来时，从首次持久化观察起等待30分钟。
  这是结束本地等待的策略，结果和扣费仍记为unknown；额度不变或历史缺少资产都不当作
  “未生成”的证明。当前历史接口没有可靠的request_id关联，系统不会按相近时间或提示词猜配结果。
- 额度查询失败也记录真实失败原因，不能使无查询地址的本地占用永久卡住。释放后仍保留
  30秒结算保护并再次查询额度；查询失败按5分钟退避，不假定退款或自动补回次数。
- 损坏的任务记录/加密句柄不能当成不存在，暂停相应处理并保留占用；维护或并发更新时
  放弃过期观察。重启保留观察批次、原等待期限和退避时间，重新登录不会重置原任务期限。

账号页无需填写原因或人工确认，自动刷新处理进度；“处理记录”只读显示系统/管理员的
时间、原任务、处理原因、额度查询状态和结果。旧失败记录、账号绑定及邮箱归属保留。
本地占用结束不表示Adobe已取消任务、生成成功或退回额度。已结束处理的任务不能重放；
未知提交按此政策关闭后也不能重新恢复轮询，重启后仍有效。

审计记录经 `GET /api/adobe/accounts/submission-resolutions?id=...` 查询。旧
`POST /api/adobe/accounts/resolve-submission` 管理接口保留兼容，仍要求原任务键、凭据版本、
说明和确认；正常页面不再要求使用它。缺失旧本地任务时审计明确记录 `task_record_state=missing`。



手动导入的 Adobe 账号可以通过“关联邮箱资产”按账号邮箱匹配已有资产，支持单个及批量操作。
管理员接口为 `POST /api/adobe/accounts/link-mailboxes`，请求 `{"ids":["adobe:账号标识"]}`，每批显式选择 1–100 个账号。
邮箱匹配忽略大小写和首尾空白；只登记当前资产的 Adobe 占用并补全来源元数据，不创建上游邮箱，不修改登录凭据或启用状态。
没有匹配资产、其他 Adobe 账号/任务已占用、资产已删除或待清理、现有来源信息冲突时，分别报告结果且不覆盖。
其他平台占用不妨碍 Adobe 关联；重复关联同一账号和资产不会新增占用。
接口返回 `linked/already_linked/unmatched/conflicts/failed` 数量及每个账号的 `results`。
若数据库占用已保存但账号文件保存失败，保留占用保护，明确报告失败；再次手动关联会补齐元数据。
邮箱管理的占用、禁用、已使用筛选、注册状态和核对结果均包含 Adobe。
自动核对与手动关联复用相同的归属保护，不覆盖其他 Adobe 账号或注册任务的占用，也不凭导入元数据新建或改写资产。
历史账号需要先由对应邮箱来源同步出现有资产；未同步的来源会报告资产未匹配，不能据单次核对宣称全部历史账号已恢复。
注册分配成功但尚未进入浏览器、邮箱归属写入失败时，会按本平台及任务释放预留；释放失败单独报告，保留原错误。

## Docker 与持久化

共享 Worker 服务/容器默认 `cfm-browser-worker`，镜像 `cfm-browser-worker:local`；旧 URL 环境变量
与 DNS 别名兼容。单会话队列负责 Python/Grok 与 Node/Adobe 生命周期；确认浏览器进程关闭后
才释放容量。CloakBrowser 当前许可只支持一个并发会话，保持 concurrency=1。

Compose 挂载 `data/browser-worker:/data`；Adobe profile 位于 `/data/adobe/<profile_id>/`，与 Grok
分开。账号 `adobe_accounts.json.enc` 和 `adobe_jobs/*.json.enc` 使用应用密钥派生的 AES-GCM
加密；注册日志使用加密 JSON 信封。不要改动或遗失解密密钥。普通回滚只换应用，不覆盖新数据。
备份范围和恢复步骤见 [核心备份](../../deploy/backup/README.md)。

开发验收不需要运行生产 Compose：使用独立容器、临时数据卷和回环端口。不要挂载线上业务数据。
实现分支允许继续审阅和本地验证；合并或发布需要另行安排。
