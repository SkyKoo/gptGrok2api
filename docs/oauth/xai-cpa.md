# xAI OAuth 授权与 CPA 交付

Grok SSO 与 xAI OAuth 分别管理。SSO 用于 Grok Web 的文字、图片与视频；xAI OAuth
授权成功后先完成 grok-4.7 质量检测，通过后交给所选 CPA，由 CPA 负责后续 Token 续期。

## 页面操作

在 xAI OAuth 页面选择 CPA 目标，然后在账号行点击授权。账号、SSO 状态、OAuth
进度、CPA 同步结果和后续操作集中在同一行。任务开始后使用当次选择的目标，修改页面
选择不会更改正在执行的任务。检测未通过时保留授权、标记风险并拦截上传，可单独复测。

授权成功与 CPA 同步成功分别记录。同步失败时保留已取得的凭据，可以在原账号行处理
交付，无需再次授权。需要上游人工验证时仍显示具体原因；不自动重复确认授权。
手动设备码和凭据导入作为补充入口，按需打开对话框，不再显示第二张凭据表格。

## 凭据与续期

参考现有 Codex 流程，CFM 保留加密的本地 OAuth 凭据副本及 CPA 交付信息。确认交付后，
CPA 是这条授权链的续期负责方。CFM 不再对该副本执行自动额度刷新、Token 续期或模型
测试，也不因为本地 Access Token 到期而提示重新授权。质量检测通过 CPA 当前凭据执行，
不使用本地旧副本。默认每 24 小时检测一次，可在页面修改或关闭；重复风险会尝试精确
移除 CPA 凭据，不支持自动移除时显示人工处理信息。详见 [降智风险检测](xai-quality.md)。

交付状态只说明凭据已交给 CPA，不保证账号永久有效、模型可用或拥有非零额度。
Grok SSO 的日常验证和图片/视频额度维护仍按原规则独立进行。

## 已同步过的历史账号

历史账号在 CPA 中可能已经自动换过 Token，CFM 中的副本可能较旧。此类账号通过
“核对 CPA”确认原目标中的账号关联，不能把“凭据已更新，待同步”直接视为需要再次上传。
核对不上传旧凭据，也不把 CPA 凭据下载后覆盖为 CFM 的日常续期来源。

CPA 上传结果未知时，先核对已有交付；远端同名且同邮箱并不足以证明新凭据已送达。
无法确认时保留待处理状态，不自动重新上传或重新授权。明确重新授权产生的新凭据与
历史交付分开记录，不能把上一次的同步成功误记在新凭据上。

## 验证与回退

本地回归使用虚构账号、模拟 xAI/CPA 服务及隔离浏览器界面，不向真实服务发起授权、
续期或上传。测试覆盖授权后自动交付、目标固定、同步失败单独处理、结果未知、历史
账号核对、凭据版本竞争及交付后的零本地续期。

新增交付信息采用兼容字段，保留本地加密格式和原始凭据。旧程序不理解 CPA 接管规则，
回退后可能重新开始 CFM 本地续期；回退时须核对这条授权链的续期负责方，不能将旧
凭据或旧数据库回灌覆盖 CPA 与 CFM 的后续业务。
