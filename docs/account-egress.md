# 账号日常出口

核对日期：2026-11-11。

注册出口和账号日常出口分别配置。注册任务会保存本次出口以支持恢复、冷却和失败排查；
注册完成不会把注册节点永久绑定到账号。

## 日常请求

GPT、Grok、Adobe 采用相同规则：

1. 手动设置的账号代理、固定节点或明确直连优先。
2. 没有单独设置、或者选择「跟随默认出口」的账号使用当前全局默认出口。
3. 更改全局默认后，继承账号的新请求使用新配置；已选定出口的在途请求保持本次选择。

参考图上传、生成提交、状态轮询、资源下载及登录态/额度维护采用账号日常规则。
注册、注册恢复和补偿仍按注册任务自己的选择执行。现有图片备用出口、资源专用代理等
高级配置继续保持各自作用域；它们不是注册出口。

「代理管理 → 账号日常出口」支持 GPT、Grok 和 Adobe。查询显示实际账号策略；选择
「跟随默认出口」可撤销账号覆盖，选择直连则明确绕过默认代理。手动修改需要填写原因。
普通 GPT 账号编辑页也可调整没有手动固定绑定的账号，调整会留下审计历史；已有手动
固定绑定需通过代理管理修改。账号凭据、可用状态和注册身份不会因调整出口而改变。

默认代理不可用时，不自动退回直连。手动固定节点被禁用、删除或地址改变时，继续报告
绑定不可用，不切换为默认出口。

## 历史账号兼容

旧版本有三类自动覆盖默认的行为：GPT 将注册出口复制到账号、Grok 注册成功后固定
日常直连、Adobe 将未配置代理解释为直连。新版本在解析账号出口时修正这些语义。

旧数据只在能够确认来源时按继承处理：

- 没有后续人工改绑历史、用途为 `registration` 的账号绑定。
- 带注册来源信息、没有其他人工改绑历史的 Grok 自动直连绑定。
- 由 2026-11-02「日常调用直连、注册保留原动态家宽」批量操作产生的确定性绑定。

未知策略、格式异常的历史、其他人工修改和普通导入的显式代理继续保留。Adobe 空代理
直接继承默认，已有账号代理仍优先。旧账号及注册日志不在启动时批量改写，因此原始
绑定证据仍可追溯；管理接口和账号编辑展示的是当前有效策略。

新写入的 `proxy_policy` 区分 `inherit` 和 `explicit`。手动选择继承会清空日常代理别名
和绑定，同时保留变更历史；新注册账号写入继承策略，不保存注册代理为日常设置。

## 验证与回退

回归使用本地模拟代理和上游，验证实际请求经过代理 A、默认切换后的代理 B，以及明确
直连三条路径；同时验证注册任务原绑定、人工覆盖、旧数据只读兼容、保存后重载与重启。
这些测试不会消耗真实账号的生成额度，也不替代部署后的运行版本和出口核对。

旧版本不理解新策略：回退程序后，旧账号保留的自动绑定可能重新生效，Adobe 空配置
也会再次变为直连。因此程序回退时必须复核三平台出口，不恢复旧数据库覆盖新业务数据。
发布记录应注明切换前后的版本、默认出口摘要、继承/人工覆盖计数和验证范围，不记录
代理密码、令牌或完整账号凭据。
